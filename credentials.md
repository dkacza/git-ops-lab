# Credential Inventory

All secrets, tokens, and credentials in use across the three stacks.

---

## Cross-stack — GitHub Actions (budget-tracker repo)

These secrets live in `dkacza/budget-tracker` → Settings → Secrets and Variables → Actions and are used by the CI workflow on every push to `main`.

| Secret | Type | Purpose |
|---|---|---|
| `GITHUB_TOKEN` | Built-in GitHub Actions token | Push images to GHCR; commit image tag updates back to git-ops-lab |
| `GIT_OPS_LAB_PAT` | Personal Access Token (PAT) | Checkout `dkacza/git-ops-lab` from the budget-tracker CI job. Rotate when CI fails with "Bad credentials". |
| `JENKINS_URL` | Plain string | Base URL of the Jenkins VM (`http://<vm-ip>:8080`); used to trigger the deploy job via curl |
| `JENKINS_API_TOKEN` | Jenkins API token | Authenticates the curl trigger call to Jenkins (`admin:<token>`) |

## Argo CD Stack

| Credential | Type | Stored at | Purpose |
|---|---|---|---|
| Argo CD admin password | Initial admin password | `argo-cd/argo-cd-admin-password.txt` (local file) | Argo CD UI and CLI login |
| GitHub webhook secret | HMAC secret (32-byte hex) | Kubernetes secret `argocd-secret` in `argocd` namespace + `argo-cd/argo-cd-webhook-secret.txt` (local backup) | Validates GitHub push webhook payloads sent to Argo CD |

The webhook secret is generated by `install-argocd-aks.sh` (`openssl rand -hex 32`) and must be registered in the `git-ops-lab` repo → Settings → Webhooks.

---

## Flux Stack

| Credential | Type | Stored at | Purpose |
|---|---|---|---|
| `GITHUB_TOKEN` (bootstrap) | PAT with `repo` scope | Environment variable at install time only | `flux bootstrap github` — commits Flux system manifests to git-ops-lab and gives Flux read access to the repo going forward |
| GitHub webhook token | HMAC secret (32-byte hex) | Kubernetes secret `webhook-token` in `flux-system` namespace + `flux/flux-webhook-token.txt` (local backup) | Validates GitHub push webhook payloads sent to the Flux webhook receiver |

The webhook token is generated by `install-flux-aks.sh` and must be registered in the `git-ops-lab` repo → Settings → Webhooks.

## Jenkins Stack

| Credential | Type | Stored at | Purpose |
|---|---|---|---|
| Jenkins admin password | Initial admin password | `jenkins/jenkins-admin-password.txt` (local file) | Jenkins UI login |
| Jenkins API token | Jenkins API token | `jenkins/jenkins-api-token.txt` (local file) + GitHub Actions secret `JENKINS_API_TOKEN` in budget-tracker repo | Allows GitHub Actions to trigger the `budget-tracker-deploy` pipeline via HTTP POST |
| `jenkins-deployer` ServiceAccount token | Kubernetes bearer token (JWT) | Kubernetes secret `jenkins-deployer-token` in `budget-tracker` namespace + embedded in `jenkins/aks-kubeconfig` | Jenkins VM authenticates to AKS to run `kubectl apply` |
| AKS kubeconfig | Kubeconfig file | `jenkins/aks-kubeconfig` (local file) + Jenkins credential store (ID: `aks-kubeconfig`, kind: Secret file) | Wires the ServiceAccount token into Jenkins pipeline steps via `withCredentials` |

The ServiceAccount is created by `setup-jenkins.sh` with a scoped Role: `get/list/watch/create/update/patch/delete` on deployments, replicasets, services, pods in the `budget-tracker` namespace, plus `get/create` on namespaces cluster-wide.

## Local files containing credentials

These files are gitignored and exist only on disk. They are backups or outputs of the install scripts.

| File | Contains |
|---|---|
| `argo-cd/argo-cd-admin-password.txt` | Argo CD initial admin password |
| `argo-cd/argo-cd-webhook-secret.txt` | GitHub webhook HMAC secret for Argo CD |
| `flux/flux-webhook-token.txt` | GitHub webhook HMAC token for Flux |
| `jenkins/jenkins-admin-password.txt` | Jenkins initial admin password |
| `jenkins/jenkins-api-token.txt` | Jenkins API token for GitHub Actions |
| `jenkins/aks-kubeconfig` | Kubeconfig with `jenkins-deployer` ServiceAccount token |
| `personal-access-token.txt` | PAT used as `GIT_OPS_LAB_PAT` — rotate here and update the GitHub secret when it expires |
